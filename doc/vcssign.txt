INTRODUCTION                                                         *vcssign*

Vcssign is a plugin for Neovim that provides integration with Git and
Subversion via a feature set which includes (but not limited to):
  • Provides signs in the |signcolumn| to show changed/added/removed lines,
    with git's staged and unstaged changes drawn as two separate sign layers.
  • Mappings to operate on hunks to stage, undo or reset against the VCS
    baseline.

Vcssign is implemented entirely in Lua which is built into Neovim and
requires no external dependencies other than the VCS binaries themselves.
Several repositories in one directory tree (including nested ones) are
supported, each resolved on its own.

Developed and tested against Neovim 0.12.4, git 2.55 and svn 1.14.5. The
newest API used is |vim.system| (since 0.10); older Neovim versions are
unverified.

==============================================================================
USAGE                                                          *vcssign-usage*

No setup required. `plugin/vcssign.vim` registers |:Vcssign| and the
functions in |vcssign-functions| work on their own.

However, automatic attaching — discovering the repository in the background
when a file is opened, refreshing the signs as you edit — is done by the
autocommands |vcssign.setup()| installs; without it, explicit actions such
as `:Vcssign refresh` still work.

Each |vcssign.setup()| call starts from the defaults and merges the table
you give it (calls do not stack): a key left out of a second call falls back
to its default.

Optional configuration can be passed to the setup function. Here is an
example with most of the default settings:
>lua
    require('vcssign').setup {
      systems = { 'git', 'svn' },
      signs = {
        add          = { text = '▎' },
        change       = { text = '▎' },
        delete       = { text = '▁' },
        topdelete    = { text = '‾' },
        changedelete = { text = '~' },
        untracked    = { text = '┆' },
        numhl        = false,
        linehl       = false,
        culhl        = false,
      },
      signs_staged = {
        add          = { text = '▎' },
        change       = { text = '▎' },
        delete       = { text = '▁' },
        topdelete    = { text = '‾' },
        changedelete = { text = '~' },
        untracked    = { text = '┆' },
      },
      signcolumn = true,
      rev = 'index',
      attach_to_untracked = true,
      max_file_length = 40000, -- Disable if file is longer than this (in lines)
      word_diff = false, -- Toggle with `<leader>tw`
      deleted_preview = false,
      current_line_blame = false, -- Toggle with `<leader>tb`
      current_line_blame_opts = {
        delay = 1000,
        virt_text = true,
        virt_text_pos = 'eol', -- 'eol' | 'overlay' | 'right_align' | 'inline'
        virt_text_priority = 200,
        ignore_whitespace = false,
        use_focus = true,
        extra_opts = {},
      },
      current_line_blame_formatter = ' <author>, <author_time:%R> - <summary> ',
      current_line_blame_formatter_nc = ' Not Committed Yet ',
      watch = true,
      update_debounce_ms = 200,
      retry_delay_ms = 1000,
      retry_max_ms = 30000,
      exec_timeout_ms = 15000,
      log_level = 'warn',
      diff = {
        mode = 'vertical',
        use_external = false,
        algorithm = 'myers',
        indent_heuristic = true,
        linematch = false,
        ignore_cr_at_eol = true,
      },
      commit = {
        message_input = 'input',
      },
    }
<

MAPPINGS                                                    *vcssign-mappings*

Once attached, every time editing settles for `update_debounce_ms`
milliseconds, the buffer is diffed against the `rev` baseline (git's staging
area / svn's BASE by default) and every hunk gets its sign. git's staged
changes use `signs_staged` and its unstaged changes use `signs`, so both
sides of a file's changes are visible at once.

The default mappings are buffer-local, installed when a buffer gets its
signs and removed again on detach. They are configured with the `keymaps`
field of the config table passed to |vcssign.setup()|. See
|vcssign-config-keymaps|.

    lhs        action                     meaning
    [c          prev_hunk                  jump to previous hunk
    ]c          next_hunk                  jump to next hunk
    <leader>hs  stage_hunk                 stage this hunk (git)
    <leader>hr  reset_hunk                 restore this hunk
    <leader>hS  stage_buffer               stage whole buffer
    <leader>hu  undo_stage_hunk            unstage this hunk
    <leader>hR  reset_buffer               restore whole buffer
    <leader>hp  preview_hunk               preview this hunk in a float
    <leader>hb  blame_line                 blame this line
    <leader>hd  diffthis                   diff against the baseline
    <leader>hD  diffthis_rev               diff against a rev
    <leader>hq  setqflist                  quickfix (planned)
    <leader>hQ  setqflist_all              quickfix all (planned)
    <leader>tw  toggle_word_diff           toggle word diff
    <leader>tb  toggle_current_line_blame  toggle inline blame

`]c` / `[c` take a count and wrap around at the ends of the buffer. Only
`hq` / `hQ` are placeholders: they answer "not implemented yet".

FUNCTIONS                                                  *vcssign-functions*

setup({cfg})                                                *vcssign.setup()*
    Configure the plugin and start the lifecycle autocommands (automatic
    attach and refresh).

    The buffers that a window shows are attached right away, so loading
    the plugin late (a lazy trigger on |BufEnter|, |:packadd|) still puts
    signs on the file in front of you: the event that would have noticed
    it has already fired. A buffer no window shows waits for its own
    |BufEnter|.

    Each call starts from the defaults and merges the table given to it
    (calls do not stack). Returns the module table.

    Parameters: ~
        {cfg} (`table?`): Configuration for vcssign.
              See |vcssign-usage| and |vcssign-config| for more details.

refresh({path})                                           *vcssign.refresh()*
    Refresh the signs of the file at {path} and of the repository
    containing it, now instead of after the debounce.

    {path} can be omitted, in which case it is resolved like |:Vcssign|:
    the current buffer's file, then the current directory. A repository
    that is not tracked yet is mounted first, then refreshed, so this can
    be the first mapping you press. The buffer showing the file is attached
    (or refreshed) as well, so signs appear even without |vcssign.setup()|
    having run. Errors are reported as notifications.

    Parameters: ~
        {path} (`string?`): A file, directory or repository root path.

attach({bufnr})                                            *vcssign.attach()*
    Put a buffer on the sign pipeline. Calling it twice is a no-op.

    Parameters: ~
        {bufnr} (`integer?`): Buffer number. Defaults to current buffer.

    Returns: ~
        (`table?`): The attach state table, or `nil` when the buffer has
        no file to diff (unnamed, `nofile`, missing on disk, or longer
        than |vcssign-config-max_file_length|).

detach({bufnr})                                            *vcssign.detach()*
    Stop drawing signs in a buffer, cancel its debounce and release this
    buffer's repository reference.

    Parameters: ~
        {bufnr} (`integer?`): Buffer number. Defaults to current buffer.

toggle({bufnr})                                            *vcssign.toggle()*
    The implementation behind |:Vcssign toggle|: turn one buffer's signs
    off or on. Turning them off empties the column and stops
    refresh-on-edit, but keeps the repository reference, so turning them
    back on redraws immediately at no extra probing cost.

    Parameters: ~
        {bufnr} (`integer?`): Buffer number. Defaults to current buffer.

    Returns: ~
        (`boolean?`): The new state, or `nil` when the buffer cannot be
        attached.

get_hunks({bufnr})                                       *vcssign.get_hunks()*
    Get the hunk array for the specified buffer.

    Parameters: ~
        {bufnr} (`integer?`): Buffer number. Defaults to current buffer.

    Returns: ~
        (`table`): The hunks currently drawn for the buffer (an empty
        table when there are none).

cli.run({fargs})                                         *vcssign.cli.run()*
    The implementation behind |:Vcssign|, kept reachable as
    `require('vcssign').cli.run(fargs)` so the API and the command can
    never drift apart.

    Parameters: ~
        {fargs} (`string[]`): The subcommand and its arguments, as
                |<f-args>| gives them.

CONFIGURATION                                                 *vcssign-config*

This section describes the configuration fields which can be passed to
|vcssign.setup()|. Tables merge key by key with the user value given higher
precedence, so a single sub-field can be overridden without redefining the
whole field; non-empty lists replace wholesale (`systems = { 'svn' }` really
means "only svn"), and empty tables count as dictionaries
(`setup({ signs = {} })` leaves the defaults alone).

systems                                               *vcssign-config-systems*
    Type: `table`, Default: `{ 'git', 'svn' }`

    The VCS systems to enable, in priority order.

exec_timeout_ms                               *vcssign-config-exec_timeout_ms*
    Type: `number`, Default: `15000`

    Timeout (in milliseconds) for a single VCS command; a command that
    exceeds it is killed and reported.

watch                                                   *vcssign-config-watch*
    Type: `boolean`, Default: `true`

    Discover changes through a filesystem watcher (git watches `.git`,
    svn watches `.svn`) and use them as a trigger to refresh signs.

    With `watch = false`, only explicit refreshes (`:Vcssign refresh`,
    `:w`, `:e!`, FocusGained) re-read the baseline.

update_debounce_ms                         *vcssign-config-update_debounce_ms*
    Type: `number`, Default: `200`

    Debounce time for buffer edits (in milliseconds): hunks are recomputed
    once editing has settled.

retry_delay_ms                                 *vcssign-config-retry_delay_ms*
    Type: `number`, Default: `1000`

    First retry delay after a failed repository liveness probe. While
    retrying, the existing repository session is kept (buffers keep their
    current baseline) and one failure warns once.

retry_max_ms                                     *vcssign-config-retry_max_ms*
    Type: `number`, Default: `30000`

    Upper bound of the exponential backoff after a failed repository
    liveness probe.

log_level                                           *vcssign-config-log_level*
    Type: `string`, Default: `'warn'`

    Plugin log level. User-facing answers ("no repository", a missing
    capability, a failed action) are not throttled by it and always show.

signs                                                   *vcssign-config-signs*
    Type: `table[extended]`
    Default: >
    {
      add          = { text = '▎' },
      change       = { text = '▎' },
      delete       = { text = '▁' },
      topdelete    = { text = '‾' },
      changedelete = { text = '~' },
      untracked    = { text = '┆' },
      numhl        = false,
      linehl       = false,
      culhl        = false,
    }
<
    Configuration for the signs of unstaged changes. The six hunk keys —
    `signs.add`, `signs.change`, `signs.delete`, `signs.topdelete`,
    `signs.changedelete`, `signs.untracked` — each take:
      • `text`: the character drawn in the sign column.
      • `numhl`, `linehl`, `culhl`: line-number / whole-line /
        cursor-line highlighting.

    The highlights `Vcssign[kind]` are used for each kind of sign. E.g.
    'add' signs use the highlights:
      • `VcssignAdd`    (for the sign text)
      • `VcssignAddNr`  (when `numhl == true`)
      • `VcssignAddLn`  (when `linehl == true`)
      • `VcssignAddCul` (when `culhl == true`)

    See |vcssign-highlight-groups|.

signs_staged                                     *vcssign-config-signs_staged*
    Type: `table[extended]`
    Default: >
    {
      add          = { text = '▎' },
      change       = { text = '▎' },
      delete       = { text = '▁' },
      topdelete    = { text = '‾' },
      changedelete = { text = '~' },
      untracked    = { text = '┆' },
    }
<
    Configuration for the signs of git staged changes. The same six hunk
    fields as |vcssign-config-signs|; it has no `numhl` / `linehl` /
    `culhl` of its own (it has no such options).

    The staged highlights are the worktree groups with a `Staged` suffix.
    See |vcssign-highlight-groups|.

signcolumn                                         *vcssign-config-signcolumn*
    Type: `boolean`, Default: `true`

    Enable/disable the sign text in the sign column.

    When disabled the signs carry no text, but `signs.numhl` /
    `signs.linehl` still get their highlights.  `signs.culhl` needs
    the sign text: it is the highlight of the sign cell on the cursor
    line (shown when 'cursorline' is set).

    vcssign never writes the window's 'signcolumn' option, so set it
    yourself: 'auto' (Neovim's default) opens the column as soon as there
    is a sign to show, 'yes' keeps it open, and 'number' draws the signs
    in the 'number' column, sharing it with the line numbers.

rev                                                       *vcssign-config-rev*
    Type: `string`, Default: `index`

    The baseline the buffer is compared against: 'index' (git's staging
    area, svn's BASE), or any revision the VCS understands.
    See |vcssign-revision|.

attach_to_untracked                       *vcssign-config-attach_to_untracked*
    Type: `boolean`, Default: `true`

    Attach to untracked files as well and draw their signs.

max_file_length                               *vcssign-config-max_file_length*
    Type: `number`, Default: `40000`

    Max file length (in lines) to attach to. Buffers with more lines than
    this get no signs at all.

word_diff                                           *vcssign-config-word_diff*
    Type: `boolean`, Default: `false`

    Highlight the intra-hunk word differences in the buffer, marking the
    actually-changed spans more precisely.

    Uses the highlight `VcssignWordDiff`. Changing the value takes effect
    immediately; `<leader>tw` toggles it.

deleted_preview                               *vcssign-config-deleted_preview*
    Type: `boolean`, Default: `false`

    Preview deleted lines as virtual lines below the hunk.

    Uses the highlight `VcssignDeleteVirtLn`. Changing the value takes
    effect immediately; it has no default mapping.

current_line_blame                         *vcssign-config-current_line_blame*
    Type: `boolean`, Default: `false`

    Adds an unobtrusive and customisable blame annotation at the end of
    the cursor line, after `current_line_blame_opts.delay` milliseconds
    of cursor stillness. `<leader>tb` toggles it.

    The annotation is also kept in `b:vcssign_blame_line` and
    `b:vcssign_blame_line_dict`. See |vcssign-variables|.

    Uses the highlight `VcssignBlame`.

current_line_blame_opts               *vcssign-config-current_line_blame_opts*
    Type: `table[extended]`
    Default: >
    {
      delay = 1000,
      virt_text = true,
      virt_text_pos = 'eol',
      virt_text_priority = 200,
      ignore_whitespace = false,
      use_focus = true,
      extra_opts = {},
    }
<
    Options for the current line blame annotation.

    Fields: ~
      • virt_text: boolean
        Whether to show a virtual text blame annotation. With `false`
        only the `b:vcssign_blame_line*` variables are set.
      • virt_text_pos: string
        Blame annotation position. Available values:
          `eol`         Right after eol character.
          `overlay`     Display over the specified column, without
                        shifting the underlying text.
          `right_align` Display right aligned in the window (falls back
                        to `eol` on a line that leaves no room).
          `inline`      Display inside the line.
      • delay: integer
        Sets the delay (in milliseconds) before blame virtual text is
        displayed.
      • ignore_whitespace: boolean
        Ignore whitespace when running blame (git only).
      • virt_text_priority: integer
        Priority of virtual text.
      • use_focus: boolean
        Enable only when the window is in focus, so an unfocused split
        shows no stale annotation.
      • extra_opts: string[]
        Extra options passed to `git-blame`.

current_line_blame_formatter     *vcssign-config-current_line_blame_formatter*
    Type: `string|function`
    Default: `' <author>, <author_time:%R> - <summary> '`

    String or function used to format the virtual text of
    |vcssign-config-current_line_blame|.

    When a string, accepts the following format specifiers:
        • `<abbrev_sha>`
        • `<rev>`
        • `<orig_lnum>`
        • `<final_lnum>`
        • `<lnum>`
        • `<author>`
        • `<author_name>`
        • `<author_mail>`
        • `<author_time>` or `<author_time:FORMAT>`
        • `<author_tz>`
        • `<committer>`
        • `<committer_mail>`
        • `<committer_time>` or `<committer_time:FORMAT>`
        • `<committer_tz>`
        • `<summary>`
        • `<previous>`
        • `<filename>`

      For `<author_time:FORMAT>` and `<committer_time:FORMAT>`, `FORMAT`
      can be any valid date format that is accepted by `os.date()` with
      the addition of `%R` for the relative form (`2 hours ago`,
      `a while ago`); a bare `<author_time>` shortens to `%Y-%m-%d`.

      A specifier the VCS cannot answer is left as written (svn has no
      `<summary>`); the default format collapses to
      `' <author>, <author_time:%R> '` on svn.

    When a function:
      Parameters: ~
        {info} Table with the blame fields behind the annotation
               (author, author_time, abbrev_sha, summary, ...).

      Return: ~
        The result of this function is passed directly to the
        `opts.virt_text` field of |nvim_buf_set_extmark| and thus must be
        a list of [text, highlight] tuples.

current_line_blame_formatter_nc
                              *vcssign-config-current_line_blame_formatter_nc*
    Type: `string|function`, Default: `' Not Committed Yet '`

    String or function used to format the virtual text of
    |vcssign-config-current_line_blame| for lines that nobody has
    committed yet (git: an all-zero object id; svn: an entry with no
    commit).

    See |vcssign-config-current_line_blame_formatter| for more
    information.

keymaps                                               *vcssign-config-keymaps*
    Type: `table[extended]`
    Default: >
    {
      ['[c'] = 'prev_hunk',
      [']c'] = 'next_hunk',
      ['<leader>hs'] = 'stage_hunk',
      ['<leader>hr'] = 'reset_hunk',
      ['<leader>hS'] = 'stage_buffer',
      ['<leader>hu'] = 'undo_stage_hunk',
      ['<leader>hR'] = 'reset_buffer',
      ['<leader>hp'] = 'preview_hunk',
      ['<leader>hb'] = 'blame_line',
      ['<leader>hd'] = 'diffthis',
      ['<leader>hD'] = 'diffthis_rev',
      ['<leader>hq'] = 'setqflist',
      ['<leader>hQ'] = 'setqflist_all',
      ['<leader>tw'] = 'toggle_word_diff',
      ['<leader>tb'] = 'toggle_current_line_blame',
    }
<
    The buffer-local default mappings: `{ lhs = 'action' }`, installed
    when a buffer gets its signs and removed again on detach.
    See |vcssign-mappings|.

    Mapping an `lhs` to `false` means: do not bind it (left for the
    user); the whole table set to `false` disables every default mapping.
    The table merges key by key, so `keymaps = { [']c'] = false }` unmaps
    only `]c`.

diff                                                     *vcssign-config-diff*
    Type: `table[extended]`
    Default: >
    {
      mode = 'vertical',
      use_external = false,
      algorithm = 'myers',
      indent_heuristic = true,
      linematch = false,
      ignore_cr_at_eol = true,
    }
<
    How a diff is displayed (`diff.mode`) and which algorithm computes it
    (`diff.algorithm`).

    Fields: ~
      • mode: string
        The diff window: `'vertical'` (a vertical split) or `'split'` (a
        horizontal one). The diff buffer is read-only and uses
        `filetype=diff`.
      • use_external: boolean
        Shell out to the VCS's own diff instead of the built-in
        `vim.text.diff`. The internal diff is the default because svn has
        no local diff backend and one implementation keeps git and svn
        behaving the same.
      • algorithm: string
        Diff algorithm to use. Values:
          `"myers"`      the default algorithm
          `"minimal"`    spend extra time to generate the smallest
                         possible diff
          `"patience"`   patience diff algorithm
          `"histogram"`  histogram diff algorithm
      • indent_heuristic: boolean
        Shift a diff to line up with indentation.
      • linematch: boolean|integer
        Refine the intra-hunk diff. `false` by default because linematch
        is quadratic in the size of a hunk and `true` means "every hunk,
        however large" (measured on an all-changed buffer: 500 lines
        1.1s, 2000 lines 69s, 5000 lines OOM). An integer applies
        linematch only to hunks up to that many lines, which is the
        bounded way to turn it on.
      • ignore_cr_at_eol: boolean
        Treat a trailing CR as part of the line ending.

commit                                                 *vcssign-config-commit*
    Type: `table[extended]`
    Default: >
    {
      message_input = 'input',
    }
<
    Options for |:Vcssign commit|.

    Fields: ~
      • message_input: string
        How the commit message is asked for (`commit.message_input`):
        `'input'` uses |vim.ui.input|'s one-line prompt. `'buffer'` is in
        the plan but not implemented yet: it warns and falls back to
        `'input'`.

on_attach                                           *vcssign-config-on_attach*
    Type: `function`, Default: `nil`

    Function called when a repository becomes attached
    (`fun(repo: vcssign.Repo)`).

    Looked up on every call, so a later |vcssign.setup()| still takes
    effect. Exceptions thrown inside are isolated (logged, nobody else
    is disturbed).

on_detach                                           *vcssign-config-on_detach*
    Type: `function`, Default: `nil`

    Function called when a repository becomes detached.

    See |vcssign-config-on_attach|.

HIGHLIGHT GROUPS                                    *vcssign-highlight-groups*

These are the highlight groups used by vcssign. Every group is defined with
`default = true`, so a colorscheme or the user can override them all and
|vcssign.setup()| never overwrites an existing definition. The groups with
an `Nr` / `Ln` / `Cul` suffix are the line-number / whole-line /
cursor-line highlights used by `signs.numhl` / `signs.linehl` /
`signs.culhl`; `delete` and `topdelete` have no `Ln`: their sign is anchored
on a line that was not removed, so a whole-line highlight would be wrong.
The staged signs use the same names with a `Staged` suffix
(`VcssignAddStaged`, `VcssignAddStagedNr`, ...): their foreground is the
worktree group's foreground blended 1:1 with `Normal`'s background, so the
staged layer is a step dimmer and the two layers on one line never look
alike; when the colours cannot be read (a `cterm`-only colorscheme, say)
they fall back to a link to the matching worktree group.

The group a sign uses is picked when the highlights are resolved: the first
of the colorscheme's git-sign groups that is actually coloured wins --
`GitGutterAdd` / `SignifySignAdd` / `DiffAddedGutter` for `add`, the
matching `GitGutter*` / `SignifySign*` names for the other types (with
`DiffModifiedGutter` for `change`, `DiffRemovedGutter` for `delete`, and
the `add` names again for `untracked`).  Only when the theme colours none
of them does the group link to `DiffAdd` / `DiffChange` /
`DiffDelete`.  The chain is gitsigns' own list without its
`GitSigns*` names; it exists because many colorschemes give `DiffAdd` and
friends a background only, which would leave the sign text in the sign
column's colour.

VcssignAdd
    Used for the text of 'add' signs.

    Links to: `DiffAdd`
                                                      *hl-VcssignChange*
VcssignChange
    Used for the text of 'change' signs.

    Links to: `DiffChange`

VcssignDelete
    Used for the text of 'delete' signs.

    Links to: `DiffDelete`
                                                   *hl-VcssignTopdelete*
VcssignTopdelete
    Used for the text of 'topdelete' signs.

    Links to: `DiffDelete`
                                                *hl-VcssignChangedelete*
VcssignChangedelete
    Used for the text of 'changedelete' signs.

    Links to: `VcssignChange`
                                                   *hl-VcssignUntracked*
VcssignUntracked
    Used for the text of 'untracked' signs.

    Links to: `VcssignAdd`

The hunk preview float defines no group of its own: it uses
`filetype=diff`'s colours, and the blame float uses `filetype=git`'s.

COMMAND                                                      *vcssign-command*

                                                                    *:Vcssign*
:Vcssign {subcmd} [path]   Run a vcssign subcommand. {subcmd} can be any of
                           the subcommands below (also what completion
                           offers). Without `[path]` it is resolved in
                           order: the current buffer's file, then the
                           current directory. The `path` argument can be a
                           file, a directory or a repository root; a path
                           outside every repository answers "no repository
                           found" explicitly (an answer, not an error).

                           Examples: >vim
                             :Vcssign toggle
                             :Vcssign refresh
                             :Vcssign stage_hunk
                             :Vcssign diffthis HEAD~1
                             :Vcssign commit
                             :Vcssign debug
<

    toggle              Turn the signs of the current buffer off / on.
                        Off = empty the column and stop refreshing; the
                        repository reference is untouched, so switching
                        back on costs no extra probing. With a `path`, act
                        on the open buffer showing that file.

    refresh             Refresh right now (skip the debounce), without
                        waiting for the filesystem watcher.

    stage_hunk          Stage the hunk under the cursor (git).
    undo_stage_hunk     Unstage the hunk under the cursor (git).
    reset_hunk          Discard the hunk under the cursor.
    stage_buffer        Stage the whole file (git).
    reset_buffer        Discard every change in the file.

    preview_hunk       Preview the hunk under the cursor in a float.
    diff                Show this file's diff.
    diffthis           Open a diff against the baseline; with an argument,
                        against that rev (`:Vcssign diffthis HEAD~1`).
    blame_line          Show the blame of the cursor line in a float.
    commit              Commit (git: the staged changes; svn: this file in
                        the working copy).
    debug               Print the mounted repositories, their references,
                        watchers and last error.

The hunk subcommands act on the hunk inside the buffer: the hunk is picked
by the cursor line and the patch is built from the buffer text, so the
buffer may hold unsaved changes — but the `reset` family requires a saved
file. These subcommands therefore only accept a file that is open; a file
that is not open is refused explicitly instead of guessed at. `stage_hunk` /
`stage_buffer` answer "no staging area" on a system without one (svn);
`reset_hunk` / `reset_buffer` refuse while the buffer has unsaved changes,
because the patch is applied to the file.

`diff` checks the capability first: a system that cannot diff gets a
one-line answer instead of a silent failure. `diffthis` is the buffer form
of `diff` (it acts on the current buffer and needs no mounted repository
reference); its argument is a rev, not a path — with one, the buffer is
compared against that rev, and if there is no difference against it, that
is said instead of opening an empty window. `preview_hunk` opens a
read-only float beside the cursor line listing the hunk's `-` / `+` lines
with `filetype=diff`; the float closes as soon as the cursor moves.
`blame_line` uses the same float for the cursor line's blame (sha / author
/ date, then the commit subject, then the source line).

==============================================================================
SPECIFYING REVISIONS                                        *vcssign-revision*

The `rev` option and `:Vcssign diffthis` accept any revision name the
underlying VCS understands. The default, `'index'`, means the VCS's local
baseline: git's staging area, svn's BASE.

Revision    Meaning ~
index       The local baseline (git: the staging area, svn: BASE)
HEAD        The last commit (git only)
HEAD~1      The parent of the last commit (git only)
<any rev>   Anything the underlying VCS understands

BUFFER VARIABLES                                           *vcssign-variables*

                        *b:vcssign_blame_line* *b:vcssign_blame_line_dict*
Provided if |vcssign-config-current_line_blame| is enabled.
`b:vcssign_blame_line` is the annotation text; `b:vcssign_blame_line_dict`

==============================================================================
ARCHITECTURE                                            *vcssign-architecture*

Bottom up; every layer only knows the one below it:

  `vcssign.vcs.*`         the git / svn adapters: commands, output parsing,
                          capability declarations
  `vcssign.repo`          one repository's session: baseline content, the
                          filesystem watcher, refresh debounce, backoff retry
  `vcssign.repo_manager`  path-to-repository lookup, reference-counted
                          attach and detach
  `vcssign.actions`       the single "intent to VCS command" layer (diff /
                          staging / committing)
  `vcssign.attach`        the per-buffer sign pipeline: baselines, debounce,
                          the on/off switch
  `vcssign.worddiff`      intra-hunk word highlighting (extmarks, own
                          namespace)
  `vcssign.preview`       virtual-line preview of deleted lines and the hunk
                          float
  `vcssign.nav`           hunk navigation: where `]c` / `[c` land
  `vcssign.blame`         inline blame: decoration, caching and the float
                          text
  `vcssign.revdiff`       the diff view: `diffthis`'s window and the text
                          for a diff against any rev
  `vcssign.keymap`        the default (buffer-local) keymaps and action
                          dispatch
  `vcssign.cli`           |:Vcssign|'s dispatch and completion
  `vcssign.autocmds`      the autocommand trigger layer (attach / refresh /
                          cleanup on exit)

Design notes: every external command's callback is cut back to the main
loop (the vim API is never touched from a libuv fast-event context);
callbacks are error-first everywhere (`cb(err, ...)`); subscribers and
hooks are isolated with `pcall`, so one bad hook cannot take the refresh
down with it. The library layers (`vcssign.vcs.*` / `vcssign.repo` /
`vcssign.repo_manager` / `vcssign.actions`) are internal; their interfaces
are documented in `impl/init/01-vcs-api.md` and `02-repo-runtime.md`.

Test scaffolding: `scripts/make_test_repos.sh` builds the fixtures,
`scripts/run_tests.sh` runs the TAP suite in a headless nvim
(`test/run.lua` + `test/*_spec.lua`); see the repository's `Makefile` for
`make test` / `make lint` / `make format`. The detailed measurement logs
and the reasoning behind each decision (D1-D46, milestones M0-M6) are in
`impl/init/00-overview.md` ... `07-signs-in-signcolumn.md`.
