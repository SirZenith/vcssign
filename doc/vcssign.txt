*vcssign.txt*     Line-level VCS signs (git / svn)                     *vcssign*

                            VCSSIGN

vcssign reflects the changes in Git / Subversion repositories straight into
the sign column: every hunk gets a sign next to its line numbers
(added / changed / deleted ...), and git's staged and unstaged changes are
drawn as two separate sign layers. Several repositories in one directory
tree (including nested ones) are supported, each resolved on its own.

  Environment: developed and tested against Neovim 0.12.4, git 2.55,
  svn 1.14.5. The newest API used is |vim.system| (since 0.10); older
  Neovim versions are unverified.
  The implementation plan (decisions D1-D46, milestones M0-M6) lives in the
  repository's `impl/README.md`.

==============================================================================
1. Installation and setup                                    *vcssign-install*

Install with any plugin manager (lazy.nvim example): >

    {
      'you/vcssign',
      config = function()
        require('vcssign').setup({
          signs = { add = { text = '▎' } },
          signcolumn = true,
        })
      end,
    }

`setup()` is optional: every layer has defaults, `plugin/vcssign.vim`
registers |:Vcssign|, and the `require('vcssign')` API works on its own. But
automatic attaching (discovering the repository in the background when a
file is opened, refreshing as you edit) is done by the autocommands `setup()`
installs — without it, explicit actions such as `:Vcssign refresh` still
work.

Each `setup()` call starts from the defaults and merges the table you
give it (calls do not stack): a key left out of a second call falls back to
its default.

2. Configuration                                             *vcssign-config*

Every key below can be passed to `require('vcssign').setup{}`. The defaults
shown are exactly what `config.lua` ships.

Complete defaults                                          *vcssign-defaults*
Every option, including the nested tables (`signs_staged` carries the same
six `text` values as `signs`; it has no `numhl` / `linehl` / `culhl` of its
own): >

    exec_timeout_ms                       15000
    watch                                 true
    update_debounce_ms                    200
    retry_delay_ms                        1000
    retry_max_ms                          30000
    log_level                             'warn'
    signs.add.text                        '▎'
    signs.change.text                     '▎'
    signs.delete.text                     '▁'
    signs.topdelete.text                  '‾'
    signs.changedelete.text               '~'
    signs.untracked.text                  '┆'
    signs.numhl                           false
    signs.linehl                          false
    signs.culhl                           false
    signs_staged.add.text                 '▎'
    signs_staged.change.text              '▎'
    signs_staged.delete.text              '▁'
    signs_staged.topdelete.text           '‾'
    signs_staged.changedelete.text        '~'
    signs_staged.untracked.text           '┆'
    signcolumn                            true
    rev                                   'index'
    attach_to_untracked                   true
    max_file_length                       40000
    word_diff                             false
    deleted_preview                       false
    current_line_blame                    false
    current_line_blame_opts.virt_text     true
    current_line_blame_opts.virt_text_pos 'eol'
    current_line_blame_opts.virt_text_priority 200
    current_line_blame_opts.delay         1000
    current_line_blame_opts.ignore_whitespace false
    current_line_blame_opts.use_focus     true
    current_line_blame_opts.extra_opts    {}
    current_line_blame_formatter          ' <author>, <author_time:%R> - <summary> '
    current_line_blame_formatter_nc       ' Not Committed Yet '
    keymaps                               (see |vcssign-keymaps|)
    diff.mode                             'vertical'
    diff.use_external                     false
    diff.algorithm                        'myers'
    diff.indent_heuristic                 true
    diff.linematch                        false
    diff.ignore_cr_at_eol                 true
    commit.message_input                  'input'
    on_attach                             nil
    on_detach                             nil

What each option means:

`systems` ({ 'git', 'svn' })~
  The VCS systems to enable, in priority order.

`exec_timeout_ms` (15000)~
  Timeout for a single VCS command; a command that exceeds it is killed and
  reported.

`watch` (true)~
  Discover changes through a filesystem watcher (git watches `.git`, svn
  watches `.svn`). With it off, only explicit refreshes (`:Vcssign refresh`,
  `:w`, `:e!`, `FocusGained`) re-read the baseline.

`update_debounce_ms` (200)~
  The debounce window for buffer edits: hunks are recomputed once editing
  has settled. 200ms is the same order as gitsigns' `update_debounce`.

`retry_delay_ms` (1000) / `retry_max_ms` (30000)~
  The first retry delay after a failed repository liveness probe and the cap
  of the exponential backoff: while retrying, the existing repository session
  is kept (buffers keep their current baseline), and one failure warns once.

`log_level` ('warn')~
  Plugin log level. User-facing answers ("no repository", missing
  capability, failed action) are not throttled by it and always show.

`signs`~
  The signs for unstaged changes. Six hunk keys — `signs.add`,
  `signs.change`, `signs.delete`, `signs.topdelete`, `signs.changedelete`,
  `signs.untracked` — each take `text` (the character drawn in the sign
  column) plus optional `numhl` / `linehl` / `culhl` (line-number / whole-
  line / cursor-line highlighting): >

    signs = {
      add          = { text = '▎' },
      change       = { text = '▎' },
      delete       = { text = '▁' },
      topdelete    = { text = '‾' },
      changedelete = { text = '~' },
      untracked    = { text = '┆' },
      numhl        = false,
      linehl       = false,
      culhl        = false,
    }

`signs_staged`~
  A separate set of signs for git staged changes; the six hunk fields
  are the same shape as `signs`: >

    signs_staged = {
      add          = { text = '▎' },
      change       = { text = '▎' },
      delete       = { text = '▁' },
      topdelete    = { text = '‾' },
      changedelete = { text = '~' },
      untracked    = { text = '┆' },
    }

`signcolumn` (true)~
  Whether the sign text is drawn at all. vcssign leaves the window's
  'signcolumn' option alone, so set it to a value that shows the column:
  Neovim's default 'auto' opens it as soon as there is a sign to show, while
  'no' and 'number' hide it. With `signcolumn = false` the signs carry no
  text, but `signs.numhl` / `signs.linehl` still get their highlights.

`rev` ('index')~
  The baseline the buffer is compared against: 'index' (git's staging area
  / svn's BASE), 'HEAD', or any revision name the VCS understands.

`attach_to_untracked` (true)~
  Attach to untracked files as well and draw their signs.

`max_file_length` (40000)~
  Buffers with more lines than this get no signs at all (large-file
  protection).

`word_diff` (false)~
  Do a word-level diff inside hunks and mark the changed spans more
  precisely (highlight group `VcssignWordDiff`). Changing the value takes
  effect immediately; `<leader>tw` toggles it.

`deleted_preview` (false)~
  Preview deleted lines as virtual lines (highlight group
  `VcssignDeleteVirtLn`). Changing the value takes effect immediately; it
  has no default keymap.

`current_line_blame` (false)~
  Show live blame at the end of the cursor line; `<leader>tb` toggles it.
  The annotation is also kept in `vim.b.vcssign_blame_line` (the text) and
  `vim.b.vcssign_blame_line_dict` (the fields behind it).

`current_line_blame_opts`~
  Inline blame options -- the same set gitsigns has:

    `delay` (1000)              milliseconds the cursor has to stand still
                                before the annotation appears
    `virt_text` (true)          draw the annotation as virtual text; with
                                `false` only the `vim.b` values are set
    `virt_text_pos` ('eol')     'eol' | 'overlay' | 'right_align' | 'inline';
                                'right_align' falls back to 'eol' on a line
                                that leaves no room for it
    `virt_text_priority` (200)  extmark priority of the annotation
    `ignore_whitespace`        (false) blame with git's `-w`, so a
                                whitespace-only change does not move the
                                annotation (git only)
    `use_focus` (true)          annotate only the focused window, so an
                                unfocused split shows no stale annotation
    `extra_opts` ({})           extra arguments for `git blame`

`current_line_blame_formatter` (' <author>, <author_time:%R> - <summary> ')~
  What the annotation says. The placeholders are gitsigns': `<author>`,
  `<author_name>`, `<author_mail>`, `<author_time>`, `<author_tz>`,
  `<committer>`, `<committer_mail>`, `<committer_time>`, `<committer_tz>`,
  `<sha>`, `<abbrev_sha>`, `<summary>`, `<previous>`, `<filename>`, `<lnum>`,
  `<orig_lnum>`, `<final_lnum>`. A specifier the VCS cannot answer is left
  as written (svn has no `<summary>`), a value can be formatted with
  `:<strftime>` (`<author_time:%Y-%m-%d>`), and `%R` is gitsigns' relative
  form (`2 hours ago`, `a while ago`); a bare `<author_time>` shortens to
  `%Y-%m-%d`. The value may also be a function
  `fun(info) -> string | {string, hl}[]`.

`current_line_blame_formatter_nc` (' Not Committed Yet ')~
  The format used for a line nobody has committed yet (git: an all-zero
  object id; svn: an entry with no `<commit>`).

`keymaps`~
  The keymap table for hunk actions: `{ lhs = 'action' }`; mapping an lhs to
  `false` means: do not bind it (left for the user; the whole table set
  to `false` disables every default mapping). The defaults are listed in
  |vcssign-keymaps|.

`diff.mode` ('vertical')~
  Open a vertical split ('vertical') or a horizontal one ('split') for the
  diff view. The diff buffer is read-only and uses `filetype=diff`.

`diff.use_external` (false) / `diff.algorithm` ('myers')~
  The diff is computed by the built-in `vim.text.diff` by default (svn has
  no local diff backend, and one implementation keeps git and svn behaving
  the same); `diff.algorithm` is one of 'myers' / 'minimal' / 'patience' /
  'histogram'.

`diff.indent_heuristic` / `diff.linematch` / `diff.ignore_cr_at_eol`~
  Indentation alignment heuristic, intra-hunk word-level refinement, and
  treating a trailing CR as part of the line ending. `diff.linematch`
  defaults to `false`: linematch is quadratic in the size of a hunk, and
  `true` means "every hunk, however large" (measured on an all-changed
  buffer: 500 lines 1.1s, 2000 lines 69s, 5000 lines OOM). To turn it on,
  set a bounded integer (linematch then applies only to hunks up to
  that many lines).

`commit.message_input` ('input')~
  How the commit message is asked for: 'input' uses |vim.ui.input|'s
  one-line prompt. 'buffer' is in the plan but not implemented yet — it
  warns and falls back to 'input'.

`on_attach` / `on_detach` (nil)~
  Functions called when a repository becomes attached / detached
  (`fun(repo)`). Optional; looked up on every call, so a later `setup()`
  still takes effect. Exceptions thrown inside the hooks are isolated
  (logged, nobody else is disturbed).

3. Commands                                                 *vcssign-commands*

                                                        *:Vcssign*
:Vcssign {sub} [path]   Run a subcommand. Without `[path]` it is resolved
                        in order: the current buffer's file, then the
                        current directory.

  Subcommands (also what completion offers): >

    :Vcssign toggle     turn the signs of the current buffer off / on
                        (off = empty the column, stop refreshing)
    :Vcssign refresh    refresh right now (skip the debounce), without
                        waiting for the filesystem watcher
    :Vcssign stage_hunk stage the hunk under the cursor (git)
    :Vcssign undo_stage_hunk
                        unstage the hunk under the cursor (git)
    :Vcssign reset_hunk discard the hunk under the cursor
    :Vcssign stage_buffer
                        stage the whole file (git)
    :Vcssign reset_buffer
                        discard every change in the file
    :Vcssign preview_hunk
                        preview the hunk under the cursor in a float
    :Vcssign diff       show this file's diff
    :Vcssign diffthis   open a diff against the baseline; with an argument,
                        against that rev (`:Vcssign diffthis HEAD~1`)
    :Vcssign blame_line show the blame of the cursor line in a float
    :Vcssign commit     commit (git: the staged changes; svn: this file in
                        the working copy)
    :Vcssign debug      print the mounted repositories, their references,
                        watchers and last error

`diff` checks the capability first: a system that cannot diff gets a
one-line answer instead of a silent failure. The `path` argument can be a
file, a directory or a repository root; a path outside every repository
answers "no repository found" explicitly (INFO, not an error).

`toggle` acts on exactly one buffer (with a `path`, on the open buffer
showing that file): turned off, the column is empty and edits no longer
refresh it; turned back on, it redraws immediately against the current
baseline. The repository reference is untouched by toggling, so the switch
costs no extra probing.

`stage_hunk` / `undo_stage_hunk` / `reset_hunk` / `stage_buffer` /
`reset_buffer` act on the hunk inside the buffer: the hunk is picked by
the cursor line and the patch is built from the buffer text (so the buffer
may hold unsaved changes — but the `reset` family requires a saved file).
These subcommands therefore only accept a file that is open; a file that is
not open is refused explicitly instead of guessed at. `stage_hunk` /
`stage_buffer` answer "no staging area" on a system without one (svn);
`reset_hunk` / `reset_buffer` refuse while the buffer has unsaved changes
(D45), because the patch is applied to the file.

`preview_hunk` opens a read-only float beside the cursor line listing the
hunk's `-` / `+` lines with `diff` syntax (`filetype=diff`, borrowing the
colorscheme's diff highlighting); the float closes as soon as the cursor
moves. `blame_line` uses the same float for the cursor line's blame (sha /
author / date, then the commit subject, then the source line). `diffthis`
is the buffer form of `diff` (it acts on the current buffer and needs no
mounted repository reference); its argument is a rev, not a path — with
one, the buffer is compared against that rev, and if there is no difference
against it, that is said instead of opening an empty window.

4. Line signs and keymaps                                      *vcssign-signs*

Once attached, every time editing settles for `update_debounce_ms`
milliseconds, the buffer is diffed against the `rev` baseline (index /
BASE by default) and every hunk gets its sign. git's staged
changes use `signs_staged` and its unstaged changes use `signs`, so both
sides of a file's changes are visible at once.

Default keymaps (all buffer-local):                        *vcssign-keymaps* >

    lhs                        action                     meaning
    [c                         prev_hunk                  jump to previous hunk
    ]c                         next_hunk                  jump to next hunk
    <leader>hs                 stage_hunk                 stage this hunk (git)
    <leader>hr                 reset_hunk                 restore this hunk
    <leader>hS                 stage_buffer               stage whole buffer
    <leader>hu                 undo_stage_hunk            unstage this hunk
    <leader>hR                 reset_buffer               restore whole buffer
    <leader>hp                 preview_hunk               preview this hunk
    <leader>hb                 blame_line                 blame this line
    <leader>hd                 diffthis                   diff against baseline
    <leader>hD                 diffthis_rev               diff against a rev
    <leader>hq                 setqflist                  quickfix (planned)
    <leader>hQ                 setqflist_all              quickfix all (planned)
    <leader>tw                 toggle_word_diff           toggle word diff
    <leader>tb                 toggle_current_line_blame  toggle inline blame

(Sign rendering, automatic attaching, `]c` / `[c` navigation, the hunk
actions, the word diff, the hunk preview, blame and the rev diff are all
wired up: switching to a file buffer draws its signs, `]c` / `[c` jump
between hunks (with a count, wrapping at the ends), `hs` / `hu` / `hr` act
on the hunk under the cursor, `hS` / `hR` on the whole file, `hp` previews
this hunk in a float, `tw` toggles the intra-hunk word highlighting, `hb`
shows this line's blame, `tb` keeps the inline blame on, `hd` / `hD` open
the diff. Only the quickfix keys `hq` / `hQ` are still placeholders — they
answer "not implemented yet"; `:Vcssign toggle` turns the whole sign layer
off.)

5. Lua API                                                     *vcssign-api*

`setup({opts})` ~
  Merge the configuration and install the lifecycle autocommands. Returns
  `require('vcssign')`.

`refresh({path})` ~
  Refresh the repository owning `path` right now (skipping the debounce).
  `path` can be omitted (resolved like |:Vcssign|). A repository that is
  not tracked yet is mounted first, then refreshed, so this can be the
  first mapping you press. The buffer showing the file is attached (or
  refreshed) as well, so signs appear even without `setup()` having run.
  Returns nil; errors are reported as notifications.

`attach({bufnr})` ~
  Put one buffer on the sign pipeline (`bufnr` defaults to the current
  buffer). Returns the state table; `nil` when the buffer has no file to
  diff (unnamed, `nofile`, missing on disk, or longer than
  `max_file_length`). Calling it twice is a no-op.

`detach({bufnr})` ~
  Stop drawing signs, cancel the debounce and release this buffer's
  repository reference.

`toggle({bufnr})` ~
  The implementation behind |:Vcssign toggle|; returns the new switch state
  (`nil` = this buffer cannot be attached). Turning it off empties the
  column and stops refresh-on-edit, but keeps the repository reference.

`get_hunks({bufnr})` ~
  The hunks currently drawn for this buffer (an empty table when there are
  none).

`require('vcssign.cli').run(fargs)` ~
  The implementation behind |:Vcssign|; equivalent to `:Vcssign {fargs}`.

The library layers (`vcssign.vcs.*` / `vcssign.repo` / `vcssign.repo_manager`
/ `vcssign.actions`) are internal: their interfaces and callback conventions
(errors first, `cb(err, ...)`; callbacks always back on the main loop) are
documented under `impl/knowledge/vcs/` and `impl/knowledge/runtime/`
(one document per module dir; `impl/README.md` is the index).

6. Highlight groups                                       *vcssign-highlights*

The sign highlight groups are derived from the hunk type: `VcssignAdd`,
`VcssignChange`, `VcssignDelete`, `VcssignTopDelete`,
`VcssignChangeDelete`, `VcssignUntracked` (linked, in order, to `DiffAdd` /
`DiffChange` / `DiffDelete` / `DiffDelete` / `VcssignChange` /
`VcssignAdd`). The groups with an `Nr` / `Ln` / `Cul` suffix are the
line-number / whole-line / cursor-line highlights used by `signs.numhl` /
`signs.linehl` / `signs.culhl`; `delete` and `topdelete` have no `Ln` —
their sign is anchored on a line that was not removed.

The staged signs use the same names with a `Staged` suffix
(`VcssignAddStaged`, `VcssignAddStagedNr`, ...): their foreground is the
worktree group's foreground blended 1:1 with `Normal`'s background, so the
staged layer is a step dimmer and the two layers on one line never look
alike; when the colors cannot be read (a `cterm`-only colorscheme, say)
they fall back to a link to the matching worktree group.

The word diff marks the actually-changed spans inside a hunk with
`VcssignWordDiff` (linked to `DiffText`); the virtual preview lines of
deleted lines use `VcssignDeleteVirtLn` (linked to `DiffDelete`). The hunk
preview float defines no group of its own — it just uses `filetype=diff`'s
colors.

The inline blame uses `VcssignBlame` (linked to `Comment`; drawn only after
`current_line_blame_opts.delay` milliseconds of cursor stillness); the
blame float uses `filetype=git`'s colors.

Every group is defined with `default = true`, so a colorscheme or the user
can override them all, and `setup()` never overwrites an existing
definition.

7. Architecture                                              *vcssign-arch*

Bottom up; every layer only knows the one below it:

  `vcssign.vcs.*`         the git / svn adapters: commands, output parsing,
                          capability declarations
  `vcssign.repo`          one repository's session: baseline content, the
                          filesystem watcher, refresh debounce, backoff retry
  `vcssign.repo_manager`  path-to-repository lookup, reference-counted
                          attach and detach
  `vcssign.actions`       the single "intent to VCS command" layer (diff /
                          staging / committing)
  `vcssign.attach`        the per-buffer sign pipeline: baselines, debounce,
                          the on/off switch
  `vcssign.worddiff`      intra-hunk word highlighting (extmarks, own
                          namespace)
  `vcssign.preview`       virtual-line preview of deleted lines and the
                          hunk float
  `vcssign.nav`           hunk navigation: where `]c` / `[c` land
  `vcssign.blame`         inline blame: decoration, caching and the float
                          text
  `vcssign.revdiff`       the diff view: `diffthis`'s window and the text
                          for a diff against any rev
  `vcssign.keymap`        the default (buffer-local) keymaps and action
                          dispatch
  `vcssign.cli`           |:Vcssign|'s dispatch and completion
  `vcssign.autocmds`      the autocommand trigger layer (attach / refresh /
                          cleanup on exit)

Design notes: every external command's callback is cut back to the main loop
(vim API is never touched from a libuv fast-event context); callbacks are
error-first everywhere; subscribers and hooks are isolated with `pcall`, so
one bad hook cannot take the refresh down with it.

Test scaffolding: `scripts/make_test_repos.sh` builds the fixtures,
`scripts/run_tests.sh` runs the TAP suite in a headless nvim
(`test/run.lua` + `test/*_spec.lua`); see the repository's `Makefile` for
`make test` / `make lint` / `make format`. The detailed measurement logs and
the reasoning behind each decision are in `impl/knowledge/overview/`
and `impl/knowledge/signs/`.
